# AI/Codex Prompt: Multi-Purpose Expense, Society Festival, and Kirana Store Management App

Build a multi-purpose application that works for:

1. Individuals who want to track personal daily expenses
2. Housing societies that want to track regular expenses, festival expenses, and flat-wise festival collections
3. Kirana store owners who want to track sales, purchases, stock, expenses, customer udhaar, and supplier dues

The app should work on web and later be compatible with Android using Capacitor.

Recommended Tech Stack:
- Frontend: React + Vite
- Mobile Android Wrapper: Capacitor
- Backend: Spring Boot REST API
- Database: PostgreSQL
- Authentication: JWT
- Export: Excel and PDF
- File Upload: Receipt image/PDF upload

Core Account Types:
- INDIVIDUAL
- SOCIETY
- KIRANA_STORE

Each account should have separate data isolation. A user should only access their own account data.

7. FESTIVAL COLLECTION TRACKER FOR SOCIETY FLATS
====================================================

Purpose:
Track how much amount is expected, collected, pending, excess, or refunded from each flat/member for festivals like Navratri, Ganpati, Diwali, etc.

Festival collection fields:
- id
- accountId
- festivalEventId
- flatId
- expectedAmount
- collectedAmount
- pendingAmount
- excessAmount
- refundedAmount
- paymentStatus: PENDING / PARTIAL / PAID / EXCESS / REFUNDED
- remarks
- createdAt
- updatedAt

Festival collection receipt fields:
- id
- festivalCollectionId
- paymentDate
- amountPaid
- paymentMode: CASH / UPI / BANK / NEFT / CHEQUE
- transactionId optional
- utr optional
- chequeNumber optional
- collectedBy
- receiptNumber
- receiptPdfUrl optional
- remarks
- createdAt

Business rules:
- Admin can generate expected collection demand for all flats for a festival.
- System should support same amount for all flats.
- System should also support custom flat-wise amount.
- Pending amount = expectedAmount - collectedAmount.
- If collectedAmount = 0, status should be PENDING.
- If collectedAmount > 0 and collectedAmount < expectedAmount, status should be PARTIAL.
- If collectedAmount = expectedAmount, status should be PAID.
- If collectedAmount > expectedAmount, status should be EXCESS.
- Allow multiple payments against one flat for the same festival.
- UTR is required for UPI/NEFT.
- Cheque number is required for CHEQUE.
- Generate receipt for each collection.
- Allow Excel import/export of flat-wise collection data.
- Allow PDF receipt export.

Festival collection dashboard cards:
- Total expected collection
- Total collected
- Total pending
- Total excess
- Paid flats
- Pending flats
- Partial flats
- Festival expense
- Festival balance

Festival collection reports:
- Festival collection summary
- Flat-wise collection report
- Pending collection report
- Paid flats report
- Partial payment report
- Excess collection report
- Collection by payment mode
- Collection by collector
- Festival profit/loss report: collectedAmount - totalFestivalExpense

Frontend pages:
- FestivalCollectionDashboard.jsx
- FestivalCollectionList.jsx
- FestivalCollectionForm.jsx
- FestivalCollectionReceipt.jsx
- FestivalCollectionReports.jsx

APIs:
- CRUD flats
- Generate festival collection demand

- Get collection reports
